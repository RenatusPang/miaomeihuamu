## 保存、预览与发布

保存链路是 Pages CMS 写入 GitHub → Actions 读取该提交 → 生成 52 个中英文静态页 → 检查链接、事实和隐藏状态 → 生成完整预览文件。

`works.html`、首页精选和搜索结构化数据均由同一内容源生成。不再用新 JSON 覆盖旧 HTML 的局部内容，避免页面与搜索数据处于不同发布版本。网站运行不需要 Python、数据库或新的前端框架；Python 仅用于 GitHub Actions 构建。

测试分支只生成 `website-preview-<commit>` artifact，保留 14 天；不执行部署。后台入口可查看最新保存提交、生成状态与当前页面版本。无法读取公开 API 时显示未知状态并提供 GitHub 记录入口，不冒称保存或发布成功。

正式上线仍需单独验收和授权。推荐顺序：先将 Pages 发布源切到 GitHub Actions，再设置仓库变量 `CMS_PUBLISH_ENABLED=true`，最后合并已验收分支。这样合并后的 main 流程会先生成并校验，再通过官方 Pages artifact 发布。不能沿用“GITHUB_TOKEN 回写 HTML 后 legacy Pages 自动部署”的假设。

## 图片、视频与历史恢复

`admin/media.html` 在浏览器本地压缩和预览图片，不自动上传、不覆盖原图、不进行生成式修图。默认最长边 2560 像素、WebP 质量 92；允许原始尺寸，提供原图与处理图放大查看。下载后通过 CMS 上传，替代文字在作品字段中填写。

本站构建策略为单图最多 20 MiB、单视频最多 24 MiB。GitHub 单文件硬上限 100 MiB、网页上传通常 25 MiB；这些不是托管 Pages CMS 的已实测上限。当前 CMS 文档与源码没有给出稳定可配置的上传大小上限；托管请求限制尚未测到边界。不引入 Git LFS、付费视频托管或图片 SaaS。

Pages CMS 原生 History 可查看历史提交，不能声称它有一键恢复。店主可用 GitHub 主账号从指定历史文件恢复为新的提交，再由相同构建流程验证。操作说明位于 `admin/guide.html`。整份作品数组恢复须保留后来其他作品的编辑，不使用 reset 或强制推送。
